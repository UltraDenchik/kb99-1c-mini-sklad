# Мини-Склад

Учебно-прикладная конфигурация «1С:Предприятие 8.3» для небольшого склада. Позволяет вести справочники товаров и контрагентов, оформлять поступление и реализацию товаров, контролировать остатки, накапливать данные о продажах и печатать расходную накладную.

## Общие сведения

| Свойство | Значение |
|---|---|
| Имя конфигурации | `Мини_Склад` |
| Синоним | «Мини-Склад» |
| Режим совместимости | 8.3.27 |
| Режим запуска | Управляемое приложение |
| Интерфейс | «Такси» |
| Язык интерфейса и встроенного языка | Русский |
| Использование модальности | Отключено |
| Синхронные вызовы платформы и внешних компонент | Отключены |
| Автор | Китушкин Данил |

В конфигурации не заданы роли и права доступа: разграничение доступа пользователей не настроено. Прикладная логика сосредоточена в модулях объектов, модулях форм, модуле менеджера документа «Реализация» и одном общем клиентском модуле.

| Справочник | `Товары` | Номенклатура товаров |

### Подсистемы

Корневая подсистема `МиниСклад` содержит четыре дочерние подсистемы, которые формируют разделы командного интерфейса:

- `Справочники` — справочники «Товары» и «Контрагенты»;
- `Документы` — документы «Поступление» и «Реализация»;
- `Регистры` — регистры накопления «ОстаткиТоваров» и «Продажи»;
- `Отчеты` — отчёт «Отчеты по остаткам».

В командном интерфейсе корневой подсистемы явно включены команды создания элементов справочников «Контрагенты» и «Товары». В навигационную панель формы документа «Реализация» добавлены команды открытия движений по обоим регистрам (по умолчанию скрыты).

## Справочники

### Товары

Неиерархический справочник товаров.

- Стандартные реквизиты: `Код`, `Наименование`.
- Длина кода — 9 символов, длина наименования — 25 символов.
- Код уникален и заполняется автоматически.
- Поиск возможен по наименованию и коду.
- Собственные реквизиты и табличные части отсутствуют.
- Используется как измерение регистров накопления и как товар в табличных частях документов.

### Контрагенты

Неиерархический справочник поставщиков и покупателей.

- Стандартные реквизиты: `Код`, `Наименование`.
- Длина кода — 9 символов, длина наименования — 25 символов.
- Код уникален и заполняется автоматически.
- Поиск возможен по наименованию и коду.
- Собственные реквизиты и табличные части отсутствуют.
- Используется в документах и в измерении `Контрагент` регистра «Продажи».

## Документы

Оба документа имеют строковый номер длиной 9 символов, автоматическую нумерацию, контроль уникальности номера и непериодическую нумерацию. Проведение разрешено, в том числе в реальном времени; проведение и отмена проведения выполняются в привилегированном режиме. При отмене проведения движения по регистрам удаляются автоматически.

### Поступление

Документ прихода товаров на склад.

**Реквизиты:**

- `Номер`, `Дата` — стандартные реквизиты документа;
- `Контрагент` — ссылка на справочник «Контрагенты», обязателен для заполнения.

**Табличная часть «Товары»:**

| Реквизит | Тип | Особенности |
|---|---|---|
| `Товар` | `СправочникСсылка.Товары` | Обязателен для заполнения |
| `Количество` | Число (10,3) | Неотрицательное |
| `Цена` | Число (10,2) | Неотрицательная |
| `Сумма` | Число (10,2) | Неотрицательная, рассчитывается автоматически |

**Формы:** `ФормаДокумента` и `ФормаСписка`.

**Проведение.** При проведении документ записывает приходные движения в регистр накопления «ОстаткиТоваров»: для каждой строки табличной части создаётся движение с видом «Приход», периодом, равным дате документа, товаром и количеством. Сумма в регистр остатков не записывается.

**Расчёт суммы.** При изменении количества или цены в строке табличной части сумма пересчитывается по формуле `Количество × Цена` через общий модуль `РаботаСФормамиКлиент`.

### Реализация

Документ расхода товаров и продажи.

**Реквизиты:**

- `Номер`, `Дата` — стандартные реквизиты документа;
- `Контрагент` — ссылка на справочник «Контрагенты», обязателен для заполнения.

**Табличная часть «Товары»:**

| Реквизит | Тип | Особенности |
|---|---|---|
| `Товар` | `СправочникСсылка.Товары` | Обязателен для заполнения |
| `Количество` | Число (10,3) | Неотрицательное |
| `Цена` | Число (10,2) | Неотрицательная |
| `Сумма` | Число (10,2) | Неотрицательная, рассчитывается автоматически |

**Формы:** `ФормаДокумента` и `ФормаСписка`.

**Контроль остатков.** Перед формированием движений документ запрашивает остатки товаров на момент времени документа. Количество по каждому товару в документе суммируется. Если требуемое количество превышает остаток, проведение отменяется (`Отказ = Истина`), а пользователю выводится сообщение для каждого недостающего товара:

> Недостаточно товара «…»! Требуется: …, в наличии: … (не хватает: …).

**Проведение.** Если остатков достаточно, документ формирует:

- расходные движения по регистру «ОстаткиТоваров» — товар и количество;
- оборотные движения по регистру «Продажи» — товар, контрагент, количество и сумма.

**Расчёт суммы.** Сумма строки пересчитывается при изменении количества или цены через общий модуль `РаботаСФормамиКлиент`.

**Печать.** В форме документа есть команда «Печать» и кнопка на командной панели. Команда формирует расходную накладную по макету `ПечатьНакладная` и открывает готовый табличный документ в режиме просмотра.

## Регистры накопления

### ОстаткиТоваров

Регистр накопления остатков.

- Измерение: `Товар` — ссылка на справочник «Товары».
- Ресурс: `Количество` — число (10,3), неотрицательное.
- Заполняется документом «Поступление» (приход) и документом «Реализация» (расход).
- Используется при контроле остатков в документе «Реализация».
- Разделение итогов включено.

### Продажи

Регистр накопления оборотов.

- Измерения: `Товар` — ссылка на справочник «Товары», `Контрагент` — ссылка на справочник «Контрагенты».
- Ресурсы: `Количество` — число (10,3), `Сумма` — число (10,2).
- Заполняется документом «Реализация».
- Является источником данных для отчёта.
- Разделение итогов включено.

## Отчёт

### ОтчетыПоОстаткам («Отчеты по остаткам»)

Отчёт на системе компоновки данных. Основная схема компоновки — `ОсновнаяСхемаКомпоновкиДанных`, вариант настроек — «Основной».

**Фактические данные.** Несмотря на название, отчёт построен не на регистре остатков, а на оборотах регистра накопления «Продажи»:

```text
РегистрНакопления.Продажи.Обороты(&НачалоПериода, &КонецПериода, Авто)
```

**Поля отчёта:**

- `Товар`;
- `Контрагент`;
- `Количество` — оборот количества;
- `Сумма` — оборот суммы.

**Параметры:** `НачалоПериода`, `КонецПериода`.

**Структура:** группировка по товару, внутри — по контрагенту. Итоги выводятся по количеству и сумме.

**Особенность.** Отчёт показывает продажи за выбранный период, а не остатки товаров на складе. Остатки на текущий момент в отчёте не выводятся.

## Печатная форма

Печатная форма расходной накладной реализована макетом `ПечатьНакладная` документа «Реализация».

**Области макета:**

- `Шапка` — номер, дата и контрагент документа;
- `ШапкаТаблицы` — заголовок табличной части;
- `Строка` — номер строки, товар, количество, цена и сумма;
- `Подвал` — итоговая сумма по документу.

**Параметры:** `Номер`, `Дата`, `Контрагент`, `НомерСтроки`, `Товар`, `Количество`, `Цена`, `Сумма`, `ВсегоСумма`.

Формирование выполняет функция `Документы.Реализация.СформироватьПечатнуюФорму(СсылкаНаДокумент)` модуля менеджера. Табличный документ настраивается без сетки и заголовков, в режиме «только просмотр», с портретной ориентацией, автоматическим масштабом и полями по 10 мм.

## Программные модули

| Модуль | Содержание |
|---|---|
| `РаботаСФормамиКлиент` | Клиентский общий модуль. Процедура `РассчитатьСумму` вычисляет сумму строки как `Количество × Цена` |
| `Документ.Поступление.МодульОбъекта` | Обработчик `ОбработкаПроведения`: формирует приходные движения по регистру «ОстаткиТоваров» |
| `Документ.Реализация.МодульОбъекта` | Обработчик `ОбработкаПроведения`: контролирует остатки, формирует расход по регистру «ОстаткиТоваров» и обороты по регистру «Продажи» |
| `Документ.Реализация.МодульМенеджера` | Функция `СформироватьПечатнуюФорму`: строит расходную накладную по макету |
| `Документ.Реализация.ФормаДокумента` | Обработчики изменения количества и цены, команда «Печать» и серверный вызов формирования печатной формы |
| `Документ.Поступление.ФормаДокумента` | Обработчики изменения количества и цены для автоматического расчёта суммы |

## Типовой сценарий работы

1. Заполнить справочники «Товары» и «Контрагенты».
2. Оформить документ «Поступление»: указать контрагента и товары с количеством и ценой. При проведении товары приходуются на склад.
3. Оформить документ «Реализация»: указать покупателя и товары. При проведении система проверит остатки, спишет товары со склада и зафиксирует продажу.
4. Распечатать расходную накладную командой «Печать» из формы документа «Реализация».
5. Проанализировать продажи за период в отчёте «Отчеты по остаткам».

## Загрузка конфигурации

Репозиторий содержит иерархическую выгрузку конфигурации в XML. Для загрузки в пустую информационную базу:

1. Открыть информационную базу в Конфигураторе.
2. Выбрать «Конфигурация → Загрузить конфигурацию из файлов».
3. Указать каталог с файлом `Configuration.xml`.
4. Обновить конфигурацию базы данных.

## Ограничения текущей реализации

- Роли и права доступа не настроены.
- Учёт ведётся только по количеству и сумме; себестоимость, партии и складские ячейки не учитываются.
- Регистр остатков не хранит цены и суммы — только количество.
- Отчёт назван «Отчеты по остаткам», но фактически показывает обороты продаж.
- Возвраты, корректировки и резервирование товаров не реализованы.
